## Quick Start

You need Node.js 18 or newer and Git.

**1. Install the CLI and register the skills.** Paste this in your terminal:

```bash
npm install -g github:al-kheder/omm && omm setup
```

On npm 12 or newer, add `--allow-git=all` to the install command, because npm 12 blocks installs from GitHub by default.

`omm setup` registers the skills with every AI tool it finds (see [Supported AI Tools](#supported-ai-tools)). It finds Claude Code only when the `claude` command is installed. If you use only the VS Code or desktop app, add the plugin from inside Claude Code instead:

```
/plugin marketplace add al-kheder/omm
/plugin install oh-my-mermaid@al-kheder-omm
```

**2. Scan your codebase.** Open your AI coding tool in your project and run:

```
/omm-scan
```

In Claude Code the skill appears as `/oh-my-mermaid:omm-scan`. The scan writes the docs to `.omm/` in your project.

**3. View the result.** In your project folder, run:

```bash
omm view
```

Then open http://localhost:3000. Use `--port <n>` to pick another port. The viewer only accepts connections from your own machine and updates live as `.omm/` changes. In the toolbar, **clean** hides file paths, and **svg** / **png** download the selected diagram, for example to put in slides for a client.

## How It Works

Your AI analyzes the codebase and generates **perspectives** — different lenses on your architecture (structure, data flow, integrations...). Each perspective contains a Mermaid diagram and documentation fields.

Every node gets **recursively analyzed**. Complex nodes become nested child elements with their own diagrams. Simple ones stay as leaves. The filesystem reflects the tree:

```
.omm/
├── overall-architecture/           ← perspective
│   ├── description.md
│   ├── diagram.mmd
│   ├── context.md
│   ├── main-process/               ← nested element
│   │   ├── description.md
│   │   ├── diagram.mmd
│   │   └── auth-service/           ← deeper nesting
│   │       └── ...
│   └── renderer/
│       └── ...
├── data-flow/
└── external-integrations/
```

The viewer auto-detects nesting from the filesystem — elements with children render as expandable groups, others as nodes.

Each element carries up to 7 fields: `description`, `diagram`, `context`, `constraint`, `concern`, `todo`, `note`.

Diagrams are flowcharts (`graph` / `flowchart`), ER diagrams (`erDiagram`) for data models such as database schemas, sequence diagrams (`sequenceDiagram`) for the order of calls in a request or protocol, or state diagrams (`stateDiagram-v2`) for lifecycles and state machines. All four are validated by `omm validate` and rendered by the viewer. Flowcharts also work as process diagrams for non-technical readers: start/end, steps, yes/no decisions, input/output, documents, subprocesses and one lane per role (`subgraph`).

## CLI

```bash
omm setup                          # Register skills with your AI tools
omm view                           # Open interactive viewer
omm config language ko             # Set content language
omm update                         # Update to latest version
```

Run `omm help` for the full command list.

## Skills

Skills are commands you run **inside your AI coding tool** (not the terminal). They start with `/`.

| Skill | What it does |
| --- | --- |
| `/omm-scan` | Analyze codebase → generate architecture docs |
| `/omm-view` | Open the architecture viewer in your browser |
| `/omm-push` | Login + link + push to cloud in one step |

## Cloud (optional)

Everything works locally — no account or server is needed. The `login`, `link`, `push` and `pull` commands only work when you point them at a compatible server:

```bash
export OMM_API_URL=https://your-server.example
omm login && omm link && omm push
```

No server is configured by default.
